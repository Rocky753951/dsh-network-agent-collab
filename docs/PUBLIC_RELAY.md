# 公共免费公网信令说明

> 本页说明可选的 Nostr 公共 Relay 信令方案。公共 Relay 仅负责转发一次性、加密的配对信令，不承载协作数据；方案默认**不自动启用、不自动发布**，只有用户明确选择公网 Relay 时才连接。

## 你需要知道的三件事

1. **无需注册或购买账号。** 客户端本地生成临时会话密钥，并通过 WebSocket 连接所选 Relay；不要求 Relay 账户、API Key 或第三方登录。
2. **免费不等于有 SLA。** 公共节点由第三方运行，可能限流、拥塞、维护、要求认证或随时下线。Relay 列表是候选列表，不是可用性承诺。
3. **Relay 不是加密保险箱。** Relay 可以看到连接时间、IP（在其网络层可见）、事件大小以及未加密的 Nostr 元数据；它可能留存、转发或分析这些信息。信令正文必须端到端加密，密钥不得发布到 Relay。

## 默认候选节点

以下只是运行时的候选地址，使用前应通过 NIP-11 能力探测，并以探测结果为准：

- `wss://relay.damus.io`
- `wss://nos.lol`
- `wss://relay.primal.net`
- `wss://relay.nostr.band`

候选节点的域名、政策、可用性与限制可能变化。客户端应显示当前实际连接的 URL、探测结果和失败原因，不应把“已连接 Relay”表述为“对方已收到”或“配对成功”。

## 公网信令如何工作

1. Host 和 Client 各自在本地生成临时会话密钥/随机会话标识，不复用 LAN `sharedSecret`、DSH Session 或 API 凭据。
2. 信令采用 Nostr NIP-01 的 `EVENT`、`REQ`、`CLOSE` 消息；推荐使用 `kind: 20000` ephemeral 事件，并设置短过期时间。
3. 事件正文是端到端加密包，至少包含会话标识、消息类型、序号、过期时间和完整性校验；Relay 只应看到必要的路由标签和加密载荷。
4. 默认并行尝试两个或三个 Relay。任一 Relay 成功发布并收到对端响应即可继续；失败或超时则切换候选，不在失败节点无限重试。
5. 信令完成后立即关闭订阅并清理本地临时密钥、事件缓存和剪贴板内容（除非用户明确选择保留诊断信息）。协作数据仍走既有 WebRTC DataChannel/LAN 传输，不经公共 Relay。

## 隐私边界

**公共 Relay 能看到的内容：**

- 连接时间、事件发布时间、事件大小、公共 Nostr 元数据与路由标签；
- Relay 服务器和上游网络可能看到客户端 IP、TLS 握手信息及请求频率；
- 加密事件可能被暂存、复制、删除或用于滥用检测。

**公共 Relay 不应看到的内容（正确实现前提）：**

- Host/Client 的 DSH Session、provider/model 凭据、LAN 密钥；
- Offer/Answer/Grant 的明文细节、协作消息与任务内容；
- 未授权情况下的本机 Agent 激活请求。

端到端加密不能隐藏流量元数据，也不能防止对端主动截图、转发或泄露已解密内容。不要通过公共 Relay 发送密码、Token、个人资料、长期身份密钥或其他不必要的敏感信息。临时密钥丢失后应重新开始配对，不要恢复使用旧会话。

## 失败、超时与切换

客户端应按下列顺序处理，而不是静默卡住：

1. **NIP-11/握手失败：** 将节点标记为不可用，展示短错误（DNS/TLS/认证/协议不兼容），切换下一候选。
2. **发布超时或被拒绝：** 记录节点返回的 `OK=false` 原因（如限流、认证、大小限制），退避后切换；不要重复高速重发同一事件。
3. **仅单向可见：** 保留订阅等待窗口；窗口结束后在界面提示“未收到对端响应”，不能宣称失败的对端已加入。
4. **所有公共节点失败：** 提供“重试候选”“改用手工复制信令包”“局域网/Tailscale”“自托管 Relay”四个明确选项。不得自动切换到未展示给用户的第三方服务。
5. **配对中途切换：** 重新生成短期会话标识和事件 ID，旧事件过期后不再接受；切换过程应在 UI 显示正在使用的节点。
6. 接收端同时校验会话哈希、对端角色、严格递增序号、一次性 nonce 与过期时间；复制密文并换 event ID 也不会再次触发信令。
7. 发布只有至少一个 Relay 返回 NIP-01 `OK=true` 才算成功；全部 `OK=false`、发送失败、超时或已关闭均明确报错，不显示“已送达”。

建议超时：单节点连接/能力探测 5 秒，发布或订阅 8 秒，完整配对等待 30 秒；实际值可按网络环境调整，并应避免无界等待。

## 手工与自托管替代方案

- **手工复制信令包：** 当所有公共节点不可用时，使用既有 Host → Client → Host → Client 的 Offer/Answer/Grant 复制流程。通过独立可信渠道传递，不把包贴到公共聊天或工单。
- **局域网 / Tailscale：** 双方网络互通时优先使用 LAN Relay；跨不可信网络使用 TLS 反向代理和 `wss://`。LAN HMAC 保证完整性，但不替代 TLS 或端到端加密。
- **自托管 Nostr Relay：** 在自己控制的 VPS/家庭服务器上运行兼容 NIP-01 的 Relay，使用 `wss://`、访问日志最小化、限流和短保留策略。将自托管地址加入显式配置并先做 NIP-11 探测；不要默认把它广播给其他用户。
- **自建轻量 WebSocket Relay：** 仅按房间转发、不持久化消息和密钥，并通过反向代理启用 TLS。此方式不需要 Nostr 生态，但仍需要一台可公网访问的主机。

自托管也不能消除端点 IP 暴露、运维、备份和法律合规责任；请明确谁能访问日志、事件保留多久，以及如何删除数据。

## 用户提示（可直接放入 UI）

> 公共 Relay 无需注册且通常免费，但由第三方运营，可能限流、维护或随时下线。我们只通过它转发短期、端到端加密的配对信令；协作数据不会经由 Relay。Relay 仍可能看到 IP、时间、大小和路由元数据，也可能保留加密事件。请勿发送密码、Token 或长期密钥。连接失败时可切换其他节点、改用手工信令、局域网/Tailscale，或配置自托管 Relay。

### 明确的操作文案

- 连接中：`正在探测公共 Relay（不会发送协作内容）…`
- 已连接：`信令 Relay：relay.example（仅表示 Relay 可用，不表示对端已收到）`
- 切换中：`当前 Relay 不可用，正在切换候选节点…`
- 全部失败：`公共 Relay 暂不可用。请选择重试、手工信令、局域网/Tailscale 或自托管。`
- 风险确认：`我了解公共 Relay 会暴露网络与时间元数据，并同意仅发送端到端加密的临时信令。`

## 配置与安全检查清单

- 仅允许 `wss://`，拒绝生产环境明文 `ws://`；
- 校验 Relay URL，禁止把用户输入拼接进任意请求；
- 使用临时会话密钥、短 TTL、事件去重和序列号，拒绝过期/重复/跨会话事件；
- Relay 返回失败时保留可诊断的分类错误，但不把完整事件或密钥写入日志；
- 不自动发布、自动注册、自动上传通讯录或自动启用未知 Relay；
- 在 UI 中让用户看到节点列表、当前节点、重试/切换/禁用开关和隐私提示；
- 定期复查候选节点的服务条款、NIP-11 限制和社区信誉。
